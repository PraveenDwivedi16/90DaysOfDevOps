# Task 1 — Why Data Gets Lost?
## Problem Statement
By default, Docker containers are **ephemeral**.

That means:

- Containers can be deleted.
- Containers can be recreated.
- Files stored inside the container are removed when the container is removed.

Example:

Container
│
├── MySQL Installed
├── Database
├── Tables
└── Records

↓
docker rm

↓
Everything is deleted

## Why Does This Happen?
Every container gets its own writable filesystem.

Docker Image
      │
      ▼
Container
      │
      ▼
Writable Layer

When the container is deleted:

- Writable layer is deleted.
- Database files are deleted.
- Logs are deleted.
- Uploaded files are deleted.

This is why databases should **never store important data only inside the container filesystem.**

# What is a Docker Volume?

A Docker Volume is a **persistent storage location** managed by Docker.

Unlike the container filesystem,

a volume exists **independently** of the container.

Meaning:

```
Container

↓

Volume

↓

Host Machine Storage
```

Even if the container is deleted,

the volume remains.

---

# Container vs Volume

```

↓

Filesystem Deleted

Deleted?

↓

NO

↓

Still Exists
```

This is why databases should store data inside volumes.

# Task 3 — Docker Bind Mounts

## What is a Bind Mount?

A Bind Mount is a way to mount a **host machine directory** directly inside a Docker container.

Unlike Named Volumes,

Docker **does not manage** Bind Mounts.

The directory is completely controlled by the user.

---

# Named Volume vs Bind Mount

Named Volume

```
Docker

↓

Manages Storage

↓

Host Disk
```

Bind Mount

```
User Folder

↓

Mounted Directly

↓

Container
```

Docker only connects them.

It does not manage the files.

---

# Why Do We Need Bind Mounts?

Suppose you are developing a website.

Folder on Laptop

```

├── index.html

├── style.css

└── script.js
```

Every time you change a file,

you don't want to rebuild the Docker image.

Instead,

Docker should immediately show the changes.

This is exactly why Bind Mounts exist.

# Problem We Faced

```

```

---

# Why Did This Happen?

This was **NOT a Docker issue**.

It was a **Git Bash (MSYS2) path conversion issue**.

Git Bash automatically converted

```
/usr/share/nginx/html
```

into

```
C:\Program Files\Git\usr\share\nginx\html
```

So Docker received the wrong destination path.

---

# Verify the Problem

We checked

```bash
docker inspect nginx-bind
```

Inside the Mounts section,

Destination became something similar to:

```
\Program Files\Git\usr\share\nginx\html
```

instead of

```
/usr/share/nginx/html
```

This confirmed that Git Bash had modified the path before Docker received it.

---

# Solution

Disable Git Bash path conversion.

```bash
MSYS_NO_PATHCONV=1 docker run -d \
  --name nginx-bind \
  -p 8081:80 \
  -v "$(pwd):/usr/share/nginx/html" \
  nginx
```

---
